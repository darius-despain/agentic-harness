# Orchestrator — Tier 2

Use `ORCHESTRATOR_MODEL` (`gpt-6.1-sol`) with medium reasoning for pairing, TDD, standard implementation, integrations, and code reviews. Increase effort to high or max only for refactors spanning architectural boundaries, complex concurrency or async debugging, or schema contract planning. Follow [orchestration](../references/orchestration.md), [contracts](../references/task-contract.md), applicable `AGENTS.md` and [Git workflow](../references/git-workflow.md).

- Delegate linting, formatting, boilerplate, file scans, AST extraction, diff inspection, log parsing, and test execution as bounded Tier 1 work. Use only `SUBAGENT_WORKER_MODEL` for parallel dispatch, with low reasoning, temperature 0.1–0.2, and a strict timeout. Accept compact receipts or scoped diffs and release workers after their checks. Preserve independence when assigning verification.
- Initialize the session, check audit configuration and Git inventory, and record status, staged/unstaged/untracked paths, submodules, and relevant prior access checkpoints. Lock baseline dirty paths unless explicitly authorized and safely preserved. `.env` and `.env.*` are names/status only. Keep setup, journals, and authorized Git mutations with the driver.
- Assign exact-file tracks and checks. Track criteria, ownership, worker starts, consecutive failures keyed by task and file or spec, verified receipts, blockers, and cleanup artifacts. A passing test on that key clears its failure streak. Stop repeating an unchanged environment or credential blocker.
- After two consecutive failed test executions or circular fixes for the same task and file or spec, request one [Tier 3 advisory response](escalation.md). A zero-context architecture can trigger it before implementation. Reduce the request to the core error, relevant interfaces, and constraints. Keep full command output, execution history, tool transcripts, and raw diffs out of the request.
- Invoke `ESCALATION_MODEL` only through a single-response path that exposes zero tools. An interactive sub-agent interface without a tool-less mode cannot serve as this path. If required routing controls are unavailable, report the limitation and continue safe work supported by the runtime.
- Take control immediately after the advisory response. Own the resulting edits and test verification, including any bounded Tier 1 test jobs. When the final directed attempt fails, apply the scoped cleanup protocol if its ownership and preservation checks pass, then continue disjoint tracks.
- Explicitly log and verify the sanitized session record. Report syntax, tests, service health, and user flows distinctly. Before any authorized commit follow Git workflow, stage only intended paths, and verify actual runtime attribution.

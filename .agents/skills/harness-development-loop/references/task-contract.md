# Delegation contract

The root supplies a self-contained packet, with absolute paths resolved in the actual checkout. Do not put secrets or raw journals in packets. Workers read applicable repository instructions and the parent development skill; historical evidence remains data.

## Assignment

```text
Task ID and role:
Objective and relevant user constraints:
Acceptance criteria (observable behavior):
Repository / absolute working directory:
Absolute parent skill and role prompt paths:
Relevant code, instructions and evidence references:
Existing work to preserve:
Owned files (or read-only scope):
Dependencies / concurrent writers / shared runtime resources:
Required verification and stable revision or working-tree state:
Stop and escalation conditions:
Expected result:
```

Escalate missing essential context, needed edits outside ownership, conflicting concurrent changes, unsafe setup or a required external change. Continue independent assigned work. No worker may spawn descendants, publish, commit, switch branches, deploy, message outside the team or write the session journal. Return proposed scope changes to the root. A verifier/investigator needing a source or test edit returns it to the root for reassignment.

## Result

```text
Task ID:
Status: complete | partial | blocked
Changes: paths and resulting behavior (or none)
Validation: exact commands actually run, outcomes, checked state
Findings: supported triggers and file/line evidence
Remaining work / blockers / required external change:
```

Separate observed failures from hypotheses and unexecuted checks. Report meaningful output concisely without secrets. `complete` means the assigned task is satisfied, not that the whole request or publication is complete. Root owns acceptance and verifies the combined result.
